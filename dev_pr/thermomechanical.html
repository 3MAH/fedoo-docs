Thermo-mechanical analysis

Coupled analysis supports 3D and plane-strain solids, with native elastic laws in small or finite strain. A monolithic problem sums the existing mechanical and thermal weakforms with the same material instance:

thermal = fd.constitutivelaw.ThermalProperties(
    thermal_conductivity=180, specific_heat=900, density=2700,
    alpha=23e-6, reference_temperature=293.15,
)
material = fd.constitutivelaw.ElasticIsotrop(E=70e9, nu=0.3, thermal=thermal)
wf = fd.weakform.StressEquilibrium(material) + fd.weakform.HeatEquation(material)
assembly = fd.Assembly.create(wf, mesh)
pb = fd.problem.NonLinear(assembly)
pb.set_dof("Temp", 293.15)
pb.set_time_integrator(fd.time.FIRST_ORDER, fd.time.BackwardEuler())
pb.set_nr_criterion("Fields", fields={
    "Disp": {"atol": 1e-5, "rtol": 1e-8},
    "Temp": {"atol": 1e-6, "rtol": 1e-8},
})

Add mechanical and thermal boundary conditions, then call pb.nlsolve. See examples/thermal/thermomechanical_monolithic.py for a complete example, including an optional FDH5 output and a Simcoon variant.

Material response and time integration

The standard ElasticIsotrop, ElasticOrthotropic, ElasticAnisotropic and CompositeUD laws accept optional thermal=ThermalProperties(...). There is no separate thermoelastic material class. Properties can also be attached after defining the mechanical material, before constructing its weakforms:

material = fd.constitutivelaw.ElasticIsotrop(E, nu)
material.set_thermal_properties(thermal)

Or pass the ThermalProperties constructor keywords directly:

material.set_thermal_properties(
    thermal_conductivity=k, specific_heat=cp, density=rho,
    alpha=alpha, reference_temperature=T_ref, coupling=False,
)

Attaching thermal properties also supplies the density used for mechanical inertia. Unattached elastic laws retain their mechanical behavior, including their existing finite-strain support.

Thermal properties enable thermal expansion and reversible mechanical feedback into heat, linearized around reference_temperature. Specific heat is the capacity per unit mass at fixed strain. Conductivity may be a constant scalar or a symmetric positive-semidefinite 3x3 tensor in current global axes. alpha may be a scalar for isotropic expansion, three normal coefficients, or six engineering strain coefficients; these use the initial global axes. Capacity and density are positive constant scalars. Spatially varying native elastic moduli remain supported. Temperatures should be absolute for physical thermal feedback.

With thermal.coupling=False, only thermal expansion remains active. The material can also be used with a mechanical weakform alone and a prescribed temperature in assembly.sv["Temp"]. A separate thermal-only problem can provide this field or its nodal history. The history transfer and synchronization of independent problems remain user-managed; there is no staggered driver yet.

SimcoonThermoMechanical calls simcoon.umat_T. For example:

material = fd.constitutivelaw.SimcoonThermoMechanical(
    "ELISO", [rho, cp, E, nu, alpha], thermal_conductivity=k,
)

These are the thermal UMAT properties, not the mechanical UMAT layout. ELISO uses one state variable. EPICP and EPKCP require explicit n_statev values (at least 8 and 14 respectively) and the corresponding kernel properties. Initialization uses start=True once; trial evaluations use start=False, including the first increment at time zero. This requires a Simcoon version whose Python umat_T binding exposes start and StepCut.

The Simcoon local thermal balance already includes capacity. Its HeatEquation therefore has no additional HeatCapacity term. Attach FIRST_ORDER/BackwardEuler to declare transient thermal evolution; the local discretization remains owned by the UMAT. Kernel thermal/cross tangents are used as supplied and can be continuum rather than exact algorithmic derivatives.

Native elastic materials instead use BackwardEuler and consistent HeatCapacity. Both displacement-temperature blocks are assembled, and the global matrix is nonsymmetric. Weakforms must share quadrature so that one assembly owns and commits the complete material state. Incompatible integration rules or different material instances in the same coupled sum are rejected. Constitutive trial updates always use the committed state; rollback rebuilds the local response for the retry’s time increment.

Finite strain with a TL heat equation

For native elastic laws, select either mechanical formulation and use reference integration for heat:

mechanical = fd.weakform.StressEquilibrium(material, nlgeom="UL")  # or "TL"
heat = fd.weakform.HeatEquation(material, nlgeom="TL")
assembly = fd.Assembly.create(mechanical + heat, mesh)

HeatEquation(nlgeom=None) (the default) follows the mechanical geometry, always using the TL thermal balance when finite strain is active. True is an alias for "TL". A fixed-geometry heat equation (nlgeom=False) is rejected in a coupled finite-strain solid.

The native constitutive response uses the same reference Hencky energy for both mechanical assemblies. It evaluates h = ln U and its dual stress T = C:(h-alpha*(temperature-T_ref)), then uses Simcoon 2.2 to convert the stress and tangent to the mechanical formulation. The total logarithmic mapping also handles anisotropic elasticity and noncoaxial stresses. It is independent of corotational history; UL mechanics accepts log_r or log.

Conductivity is specified as a constant spatial tensor k in current global axes. The thermal equation uses its pullback K0 = J F^-1 k F^-T, reference density and reference-volume heat sources. Heat capacity is rho0*c; material density need not be updated as the body deforms. The deformation derivative of K0 contributes to the thermal versus displacement block. The reference thermal gradients and quadrature measure are preserved when sharing an assembly with UL mechanics, without duplicating the constitutive state. Consistent mechanical inertia also uses reference mass.

Finite-strain reversible feedback uses actual absolute temperature:

r0 = -temperature * beta:(h-h_start) / dt
beta = C:alpha

Its deformation and temperature derivatives are assembled. This corresponds to constant specific heat at fixed logarithmic strain. The small-strain model retains feedback linearized at T_ref. coupling=False disables this feedback in either formulation. Positive absolute temperature is required.

The native example accepts --nlgeom TL or --nlgeom UL. Both use TL heat integration. Gauss-point HeatFlux and ReferenceHeatFlux fields contain the spatial heat flux and its reference counterpart. A heat-only problem can also use a prescribed total deformation gradient in assembly.sv["F"].

Field convergence

Fields checks each field independently using:

norm(residual_f) < atol_f + rtol_f * reference_f

All fields must pass. The reference defaults to the current recovered force norm for that field, including reactions; a fixed nonnegative reference can be supplied per field. Choose an absolute tolerance appropriate to the units of each field, especially for vanishing reaction/load references. No arbitrary force scale of one is substituted by this criterion.

The maximum normalized field error must be below one; the scalar tol or tol_nr does not set the Fields residual threshold. Other criteria retain their existing behavior. pb.nr_errors reports the latest per-field errors. Fields must cover every free DOF, including global DOFs, without overlaps. MPC forces are reduced before checking the master DOFs of each field. Constraints that mix fields with different units are not a supported convergence partition.

Current limits

Static mechanics and undamped endpoint Newmark mechanics can be combined with the thermal solve. The Simcoon umat_T adapter remains small strain pending its finite-strain constitutive audit and interface changes. Plane stress, axisymmetry, incompressibility projections, material-frame transformations, damped coupled mechanics and generalized-alpha away from the endpoint are not yet supported. These modes raise explicit errors rather than silently dropping coupling terms. A staggered coupling driver remains a subsequent step. Finite thermoelasticity uses the Simcoon 2.2 conversion API; the package minimum is now 2.2.
